BuMIS Frontend Phase 02 - Admin Pages API Writeup

Scope
- Admin Users
- Admin Roles
- Admin Permissions
- Audit Logs
- System Settings

Base URL
- Postman collection: `http://localhost:3000/api`
- Frontend client base: `/api` by default, or `VITE_API_BASE_URL` if set
- Auth: all endpoints below require `Bearer <accessToken>`

Frontend files
- `frontend/src/api/users.api.js` exports `usersApi`
- `frontend/src/api/roles.api.js` exports `rolesApi`
- `frontend/src/api/permissions.api.js` exports `permissionsApi`
- `frontend/src/api/audit.api.js` exports `auditApi`
- `frontend/src/api/settings.api.js` exports `settingsApi`
- `frontend/src/api/index.js` re-exports all API modules

Frontend page files
- `frontend/src/pages/admin/AdminUsersPage.jsx`
- `frontend/src/pages/admin/AdminRolesPage.jsx`
- `frontend/src/pages/admin/AdminPermissionsPage.jsx`
- `frontend/src/pages/audit/AuditLogsPage.jsx` as used by `frontend/src/routes/AppRoutes.jsx` for admin audit access
- `frontend/src/pages/admin/SystemSettingsPage.jsx`

====================================================================
1) ADMIN USERS
====================================================================

Purpose
- Manage platform users, activation state, role assignment, permissions, and profile details.

APIs to use

1. GET `/users`
- Frontend helper: `usersApi.list()`
- Optional query parameter:
  - `businessId`

Sample request
```http
GET /api/users?businessId=1e8b7a8c-4d2d-4e8d-a11c-7f2e4f7d1011
Authorization: Bearer <accessToken>
```

Sample response
```json
[
  {
    "id": "8a1f6f86-2e89-4a8c-9c7f-6dce0d9a1001",
    "fullName": "Jane Doe",
    "email": "jane@example.com",
    "phone": "+255700000001",
    "position": "Accountant",
    "status": "active",

    "roleId": "r-001"
  }
]
```

4) AUDIT LOGS
====================================================================

Purpose
- Trace platform activity, filter events, and summarize actions for admin oversight.

APIs to use

1. GET `/audit/logs`
- Frontend helper: `auditApi.logs(params)`
- Query parameters:
  - `page`
  - `limit`
  - `businessId`
  - `userId`
  - `action`
  - `entityName`
  - `search`
  - `dateFrom`
  - `dateTo`

Sample request
```http
GET /api/audit/logs?page=1&limit=20&action=login_success
Authorization: Bearer <accessToken>
```

Sample response
```json
{
  "items": [
    {
      "id": "a-log-001",
      "businessId": "1e8b7a8c-4d2d-4e8d-a11c-7f2e4f7d1011",
      "userId": "8a1f6f86-2e89-4a8c-9c7f-6dce0d9a1001",
      "action": "login_success",
      "entityName": "Auth",
      "entityId": "8a1f6f86-2e89-4a8c-9c7f-6dce0d9a1001",
      "ipAddress": "127.0.0.1",
      "userAgent": "Mozilla/5.0",
      "metadata": {
        "email": "jane@example.com",
        "success": true
      },
      "user": {
        "id": "8a1f6f86-2e89-4a8c-9c7f-6dce0d9a1001",
        "fullName": "Jane Doe",
        "email": "jane@example.com"
      },
      "createdAt": "2026-07-01T09:20:00.000Z"
    }
  ],
  "page": 1,
  "limit": 20,
  "total": 1
}
```

2. GET `/audit/summary`
- Frontend helper: `auditApi.summary(params)`
- Same optional filters as logs, but used for a compact summary card or chart.

Sample response
```json
{
  "total": 1,
  "byAction": {
    "login_success": 1
  }
}
```

Frontend note
- Use `auditApi.logs()` for the table.
- Use `auditApi.summary()` for action distribution charts or KPI cards.

====================================================================
COMMON FRONTEND USAGE
====================================================================

Recommended import style
```js
import {
  usersApi,
  rolesApi,
  permissionsApi,
  auditApi,
  settingsApi,
} from '../../api/index.js'
```

Short usage sample
```js
const loadAdminUsers = async () => {
  const users = await usersApi.list()
  return users
}

const loadAudit = async () => {
  const [logs, summary] = await Promise.all([
    auditApi.logs({ page: 1, limit: 20 }),
    auditApi.summary(),
  ])
  return { logs, summary }
}

const saveBusinessSettings = async (payload) => {
  return settingsApi.updateBusiness(payload)
}
```

Final note
- These five admin areas are now covered with the exact frontend modules, backend endpoints, and example payloads.
- The Users, Roles, and Permissions pages are CRUD-heavy.
- Audit Logs and Settings are mostly query/filter/update flows, so they should be straightforward to wire into tables, panels, and forms.
