BuMIS Frontend Phase 03 - Business Owner Pages API Writeup

Scope
- Dashboard
- Products
- Customers
- Vendors
- Inventory

Base URL
- Postman collection: `http://localhost:3000/api`
- Frontend client base: `/api` by default, or `VITE_API_BASE_URL` if set
- Auth: all endpoints below require `Bearer <accessToken>`
- Business context: these endpoints use the logged-in business owner scope

Frontend API files
- `frontend/src/api/dashboard.api.js` exports `dashboardApi`
- `frontend/src/api/products.api.js` exports `productsApi`
- `frontend/src/api/customers.api.js` exports `customersApi`
- `frontend/src/api/vendors.api.js` exports `vendorsApi`
- `frontend/src/api/inventory.api.js` exports `inventoryApi`
- `frontend/src/api/index.js` re-exports all API modules

Frontend page files
- `frontend/src/pages/business/BusinessDashboardPage.jsx`
- `frontend/src/pages/business/ProductsPage.jsx`
- `frontend/src/pages/business/CustomersPage.jsx`
- `frontend/src/pages/business/VendorsPage.jsx`
- `frontend/src/pages/business/InventoryPage.jsx`

====================================================================
COMMON FRONTEND USAGE
====================================================================

Recommended import style
```js
import {
  dashboardApi,
  productsApi,
  customersApi,
  vendorsApi,
  inventoryApi,
} from '../../api/index.js'
```

Short usage sample
```js
const loadDashboard = async () => {
  const summary = await dashboardApi.summary()
  const lowStock = await dashboardApi.lowStock()
  return { summary, lowStock }
}

const loadProducts = async () => {
  const products = await productsApi.list()
  const alerts = await productsApi.lowStock()
  return { products, alerts }
}

const saveStockIn = async (payload) => {
  return inventoryApi.stockIn(payload)
}
```

Final note
- These five business-owner pages are now covered with the actual API modules, backend endpoints, and example payloads.
- Dashboard is the aggregated overview.
- Products, Customers, and Vendors are CRUD-driven modules.
- Inventory is action-driven and should be wired around transaction tables, low-stock alerts, and stock movement forms.
