BuMIS Frontend Phase 04 - Business Owner Pages API Writeup

Scope
- Reports
- Users
- Subscription

Base URL
- Postman collection: `http://localhost:3000/api`
- Frontend client base: `/api` by default, or `VITE_API_BASE_URL` if set
- Auth: all endpoints below require `Bearer <accessToken>`
- Business context: these endpoints use the logged-in business owner scope unless a specific `businessId` is provided

Frontend API files
- `frontend/src/api/reports.api.js` exports `reportsApi`
- `frontend/src/api/users.api.js` exports `usersApi`
- `frontend/src/api/roles.api.js` exports `rolesApi`
- `frontend/src/api/permissions.api.js` exports `permissionsApi`
- `frontend/src/api/subscriptions.api.js` exports `subscriptionsApi`
- `frontend/src/api/index.js` re-exports all API modules

Frontend page files
- `frontend/src/pages/reports/ReportsPage.jsx`
- `frontend/src/pages/business/UsersPage.jsx`
- `frontend/src/pages/business/SubscriptionPage.jsx`

====================================================================
1) REPORTS
====================================================================

Purpose
- Provide business reporting for sales, customers, products, inventory, invoices, and trends.
- The current UI shell is `ReportsPage`, which is a scaffold, but the backend already exposes the reporting APIs needed for a full dashboard.

APIs to use

1. GET `/reports/sales/daily`
- Frontend helper: `reportsApi.dailySales(params)`
- Optional query parameters:
  - `date`

Sample request
```http
GET /api/reports/sales/daily?date=2026-07-06
Authorization: Bearer <accessToken>
```

Sample response
```json
{
  "count": 4,
  "revenue": 450000,
  "discounts": 12000,
  "tax": 0,
  "netSales": 450000
}
```

- The business route is currently a scaffold, but the backend and API client already support the full subscription flow.


Subscription management notes
- `subscriptionsApi.plans()` is the read path for the business subscription page.
- `subscriptionsApi.business(businessId)` is the current-status path for the business subscription card or summary panel.
- `subscriptionsApi.createBusinessSubscription(payload)` and `subscriptionsApi.renew(id, payload)` are management actions and require `subscription.manage`.
- The admin-only page also uses `adminApi.subscriptions()`, `adminApi.renewSubscription()`, and `adminApi.updateSubscriptionStatus()`, but those are not part of the business route.

====================================================================
COMMON FRONTEND USAGE
====================================================================

Recommended import style
```js
import {
  reportsApi,
  usersApi,
  rolesApi,
  permissionsApi,
  subscriptionsApi,
} from '../../api/index.js'
```

Short usage sample
```js
const loadReports = async () => {
  const daily = await reportsApi.dailySales({ date: '2026-07-06' })
  const trends = await reportsApi.salesTrends({ dateFrom: '2026-01-01', dateTo: '2026-07-06' })
  return { daily, trends }
}

const loadUsers = async (businessId) => {
  const users = await usersApi.list({ businessId })
  const roles = await rolesApi.list()
  const permissions = await permissionsApi.list()
  return { users, roles, permissions }
}

const loadSubscription = async (businessId) => {
  const plans = await subscriptionsApi.plans()
  const current = await subscriptionsApi.business(businessId)
  return { plans, current }
}
```

Final note
- The Reports, Users, and Subscription business pages can all be backed by these modules immediately.
- Reports is the analytics surface.
- Users is the staff and access-control surface.
- Subscription is the plan and renewal surface.
- The examples above match the current backend controllers and service return shapes.
