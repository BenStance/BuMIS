BuMIS Frontend Phase 01 - Admin Pages API Writeup

Scope
- Admin Dashboard
- Businesses
- Subscription
- Revenue Analysis

Base URL
- Postman collection: http://localhost:3000/api
- Frontend client: `/api` by default, or `VITE_API_BASE_URL` if set
- Auth: all admin endpoints require `Bearer <accessToken>`
- Required admin permission: usually `Platform Administrator` with the relevant permission checks in backend

====================================================================
1) ADMIN DASHBOARD
====================================================================

Purpose
- Show platform overview cards, activity, and chart-ready summary data.
- Good place for KPI cards and quick platform health indicators.

APIs to use

1. GET `/admin/dashboard`
- Frontend helper: `adminApi.dashboard()`
- Use for:
  - Total businesses
  - Active businesses
  - Expired subscriptions
  - Active users
  - Total sales invoices generated
  - Platform revenue
  - New registrations
  - System health

Sample request
```http
GET /api/admin/dashboard
Authorization: Bearer <accessToken>
```

Sample response
```json
{
  "totalBusinesses": 124,
  "activeBusinesses": 118,
  "expiredSubscriptions": 9,
  "activeUsers": 342,
  "totalSalesInvoicesGenerated": 18420,
  "platformRevenue": 24500,
  "newRegistrations": 11,
  "systemHealth": {
    "status": "ok"
  }
}
```

2. GET `/admin/statistics`
- Frontend helper: `adminApi.statistics()`
- Use for charts on the dashboard:
  - Businesses by subscription plan
  - Businesses by status
  - Average users per business

Sample request
```http
GET /api/admin/statistics
Authorization: Bearer <accessToken>
```

Sample response
```json
{
  "totalBusinesses": 124,
  "newBusinessesThisMonth": 11,
  "businessesBySubscriptionPlan": {
    "Starter": 40,
    "Growth": 58,
    "Enterprise": 26
  },
  "businessesByStatus": {
    "active": 118,

  "averageUsersPerBusiness": 2.75
}
```

3. GET `/admin/users/active?page=1&limit=20`
- Frontend helper: `adminApi.activeUsers(params)`
- Use for a dashboard table or a "recently active users" panel.
- Optional filters:
  - `page`
  - `limit`
  - `search`
  - `businessId`

====================================================================
4) REVENUE ANALYSIS
====================================================================

Purpose
- Show platform-wide subscription revenue and performance breakdowns.
- This page is chart-friendly without needing extra endpoints.

APIs to use

1. GET `/admin/revenue`
- Frontend helper: `adminApi.revenue()`
- Use for:
  - Monthly subscription revenue
  - Annual revenue projection
  - Revenue by subscription plan
  - Active vs expired subscriptions
  - Renewal rate

Sample request
```http
GET /api/admin/revenue
Authorization: Bearer <accessToken>
```

Sample response
```json
{
  "monthlySubscriptionRevenue": 2450,
  "annualRevenue": 29400,
  "revenueBySubscriptionPlan": {
    "Starter": 400,
    "Growth": 1500,
    "Enterprise": 550
  },
  "activeVsExpiredSubscriptions": {
    "active": 118,
    "expired": 9
  },
  "subscriptionRenewalRate": 0.93
}
```

Frontend chart suggestions
- Bar chart: `revenueBySubscriptionPlan`
- Doughnut chart: `activeVsExpiredSubscriptions`
- KPI cards:
  - `monthlySubscriptionRevenue`
  - `annualRevenue`
  - `subscriptionRenewalRate`

====================================================================
COMMON FRONTEND MAPPING
====================================================================

adminApi methods already available
- `adminApi.dashboard()`
- `adminApi.businesses(params)`
- `adminApi.business(id)`
- `adminApi.statistics()`
- `adminApi.activeUsers(params)`
- `adminApi.subscriptions(params)`
- `adminApi.revenue()`
- `adminApi.loginAsBusiness(id)`
- `adminApi.renewSubscription(id, payload)`
- `adminApi.updateSubscriptionStatus(id, payload)`

subscriptionsApi methods that may also be useful on the Subscription page
- `subscriptionsApi.plans()`
- `subscriptionsApi.createPlan(payload)`
- `subscriptionsApi.updatePlan(id, payload)`
- `subscriptionsApi.deletePlan(id)`
- `subscriptionsApi.createBusinessSubscription(payload)`
- `subscriptionsApi.renew(id, payload)`
- `subscriptionsApi.business(businessId)`

Frontend API paths
- `frontend/src/api/admin.api.js` exports `adminApi`
- `frontend/src/api/business.api.js` exports `businessApi`
- `frontend/src/api/subscriptions.api.js` exports `subscriptionsApi`
- `frontend/src/api/dashboard.api.js` exports `dashboardApi`
- `frontend/src/api/reports.api.js` exports `reportsApi`
- `frontend/src/api/index.js` re-exports all API modules

Sample consumption
```js
import { adminApi, subscriptionsApi } from '@/api'

const loadAdminDashboard = async () => {
  const summary = await adminApi.dashboard()
  const revenue = await adminApi.revenue()
  return { summary, revenue }
}

const loadAdminSubscriptions = async () => {
  const items = await adminApi.subscriptions({ page: 1, limit: 20 })
  const plans = await subscriptionsApi.plans()
  return { items, plans }
}
```

Final note
- The four admin pages can be built cleanly from the endpoints above.
- The dashboard and revenue pages already have chart-ready aggregated responses.
- The businesses and subscriptions pages use paginated list APIs with filters, plus detail/action endpoints for modal or drawer workflows.
